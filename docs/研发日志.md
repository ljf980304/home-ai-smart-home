## 2026-08-26 — 本地后端落地（Express + node:sqlite）+ 米家真机接入探索

**对应提交**：`2adfeef`（后端 + proxy 切换）

### 背景

前端业务一期已跑通（设备/总览/场景，契约先行），但数据挂在 APIfox mock 上，没有持久化、也没有真实后端。本日把**本地后端**落地，实现 `docs/api/接口清单.md` 全部接口，前端零改动切到真实接口；同时开始探索接入第一台真实设备（米家台式风扇 xiaomi.fan.p70）。

### 本次做了什么

1. **新增 `apps/server` 后端（Express 5 + TypeScript）**
   - 数据库用 **Node 内置 `node:sqlite`**（`DatabaseSync`），零原生依赖，Windows 上免去 node-gyp / better-sqlite3 编译。
   - 三张表：`devices`（state 以 JSON 文本存储）、`scenes`；首次启动自动建表 + 种子数据（7 台设备 + 4 个场景，与契约建议数据一致）。
   - 接口按 `接口清单.md` 实现：`GET /devices`、`PATCH /devices/:id`、`GET/POST/DELETE/PATCH /scenes`；`state` 更新按设备类型白名单合并；404/400 处理。
   - 根脚本新增 `dev:server` / `dev:web`，`pnpm dev` 同时起前后端。

2. **前端切到真实后端**
   - vite proxy 默认目标改 `http://127.0.0.1:3001`（`.env.local` 同步更新），前端**零改动**。
   - 契约文档、后端、SQLite 种子数据三者对齐。

3. **米家真机接入探索（进行中）**
   - 确认风扇型号 **xiaomi.fan.p70**：Wi-Fi 直连、无需网关、miIO 局域网协议。
   - 网络探测：IP `192.168.137.147`（电脑热点网段）、ARP 确认 MAC、ping 通；但 TCP/UDP 54321、mDNS 均无响应。
   - **诊断结论**：Windows 移动热点不能共享"Wi-Fi 上网"，热点无外网 → 风扇连上热点但连不上米家云 → 局域网控制服务未启动。米家 App 的"在线"是缓存旧状态。
   - **token 提取**：验证了米家云登录接口链路可用（`miio-token-extractor`），本地工具提取。已绑定设备不会泄露 token（`miIO.info` 返回 `token:"0"`），必须走云端提取。

### 关键决策

| 决策 | 结论 | 理由 |
|---|---|---|
| SQLite 驱动 | Node 内置 `node:sqlite` | 零原生依赖、免编译；已验证可用 |
| 契约/种子对齐 | 后端 state 按类型白名单合并 | 与判别联合契约一致，拒绝脏数据 |
| 前端切换方式 | 只改 proxy 目标 | 契约先行红利：组件零改动 |

### 遇到的问题与解决

1. **pnpm 拦截 esbuild 构建脚本**（tsx 依赖）：`pnpm-workspace.yaml` 配 `allowBuilds.esbuild: true`。
2. **node:sqlite `.all()` 返回类型**与自定类型不重叠：`as unknown as` 显式转换。
3. **残留 vite 进程占用 5173/5178**：TaskStop 只杀 pnpm 壳、node 子进程存活；用 `netstat` + `taskkill` 清理（VSCode 托管的那台是用户自己的，保留）。
4. **Windows 终端中文乱码**（POST 场景名）：仅测试时 curl 编码问题，DB 存 UTF-8 正常，不影响前端（fetch 走 UTF-8）。

### 验证

- `pnpm -F server typecheck` ✅、`pnpm lint` ✅、`pnpm build`（全仓）✅
- curl 冒烟：设备/场景全部接口、state 合并、404、数据持久化（改挡位后重启保留）✅
- 经 vite proxy 全链路 `GET/PATCH /api/devices` ✅（前端零改动）

### 遗留 / 下一步

- **米家适配层**（明天）：
  - 用户在终端跑 `tools/mi-token` 提取风扇 token（已验证链路通）
  - 解决风扇外网问题（连回有外网的路由器 / 手机 USB 共享给热点），使 miIO 服务启动
  - 探测风扇 miot 规格（siid/piid）→ 写适配层映射 `FanState` → 后端注册真实设备
- 场景联动（场景绑定设备动作 + `POST /scenes/:id/run`）为备选方向

## 2026-08-25 — 设备模型重构 + 风扇接入 + 卡片统一规范

**对应提交**：`ce7d8c5`（前端业务一期）、`e3f4b16`（本次）

### 背景

第一期前端业务已落地：Naive UI + Pinia + APIfox mock 的真实 HTTP 链路、设备/总览/场景三页、类型与 service 层、`docs/api/接口清单.md` 契约文档。本期以此为基础，把**设备数据模型**往商用方向加固，并接入第一台真实设备（小米桌面循环扇）。

### 本次做了什么

1. **设备模型重构：按类型判别联合**
   - `Device` 从"扁平可选字段"（`brightness?/temperature?/speed?` 堆在一个接口里）改为**判别联合**：公共属性（id/name/type/room/online/power）+ 各类型专属 `state`。
   - 新增 `LightState` / `AirConditionerState` / `FanState`，`type` 决定 `state` 的形态。
   - 理由：契约先行、面向多人多端开发。判别联合让接口自文档化，后端与将来的米家/Matter 适配层映射关系一目了然；设备类型再多也不污染公共接口。
   - 代价：一次性的类型 / service / store / 视图 / 契约文档同步（此刻代码量小，重构成本最低）。

2. **接入小米桌面循环扇**
   - `FanState` 完整建模：挡位 `windLevel`(1-4)、模式 `mode`(直吹/自然)、左右摇头 `swingH` + 角度 `swingHAngle`(30/60/90/120)、上下摇头 `swingV` + 角度 `swingVAngle`(30/60/90/100)、定时 `timerHours`(0-4h)。
   - 契约、前端、APIfox mock 三处同步为 state 结构。

3. **设备卡片统一规范**
   - 固定高度、四区块布局：顶部行（名称 + 标签，标签右对齐）→ 房间（左对齐）→ 核心操作区 → 「···」更多按钮。
   - 核心操作区**默认显示前 4 个控件、每行一个**；控件总数 ≤ 4 不显示「···」，> 4 显示「···」打开**完整控制弹窗**。
   - 控制项改为**数据驱动**：`DEVICE_CONTROLS` 每类型一份清单（switch / radio / slider 三种控件），调整数组即可配置默认显示项。
   - 新增 `DeviceControlModal`（完整控制弹窗）、`deviceUi.ts`（共享控制清单与交互）。

4. **空调补温度控制**：`setTemperature`（16-30℃ 滑块），卡片直接可用。

### 关键决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 数据模型形态 | 按类型判别联合 | 契约自文档化；为适配层铺路；避免 Device 变"大杂烩" |
| 卡片默认控件 | 4 个 / 超出收「···」弹窗 | 老人友好 + 信息密度平衡；高频操作直达，低频进弹窗 |
| 风扇挡位建模 | `windLevel` 1-4（非 0-100 连续） | 贴合真实设备 4 档物理语义 |
| 分段控件 | `n-radio-group` + `n-radio-button` | naive-ui 2.45.2 无 Segmented 组件 |

### 遇到的问题与解决

1. **APIfox PATCH 返回 200 + 空 body**：`res.json()` 抛错导致设备控制回滚。修复 `http.ts`：空 body 直接返回 `undefined`。
2. **场景接口字段不一致**（mock 用 `active`，契约用 `enabled`）：按契约先行原则，对齐 APIfox 的示例数据。
3. **naive-ui 无 `Segmented` 组件**（2.45.2）：改用 `n-radio-group` + `n-radio-button`，视觉即分段按钮。
4. **判别联合下模板收敛**：灯光/空调/风扇各自读取 `state` 字段，靠 `v-if="device.type === 'fan'"` 等判别在 vue-tsc 中正确收敛。

### 验证

- `pnpm -F dashboard typecheck` ✅
- `pnpm lint` ✅
- `pnpm -F dashboard build` ✅
- curl 验证 mock 链路：`GET /api/devices`（state 结构）、`PATCH /api/devices/fan-001`（200）

### 遗留 / 下一步

- 场景编排（拖拽）、留言板、身份特征管理（报告第二/三期范围）
- 设备适配层（米家 SDK 映射到本契约）
- `swing` 相关控制需要真实设备联调验证
- 更多真实设备类型（电视、门锁、净水器等）按相同模式扩展
